# F6 — 對話視窗前端 | Requirements

> 狀態：✅ 已確認
> 負責人：模組三
> 相依：W1 回傳的結構化 JSON + 自然語言摘要、WebSocket 推播
> 技術：HTML / CSS / 原生 JS（不使用 React）

---

## 一、元件定位

F6 是 Dashboard 上的對話介面，讓指揮官/評審與模組三的 AI 顧問互動。F6 只負責「呈現」和「收集輸入」，所有邏輯都在後端（W2/W1）。

---

## 二、功能需求

### 佈局與空間

#### REQ-1：可收合/展開的對話面板

- 預設狀態為**收合**，在 Dashboard 右側顯示一個明顯的浮動按鈕（例如帶圖示的圓形或膠囊按鈕）。
- 點擊按鈕後**展開**為右側面板（約 400~450px 寬）。
- 展開時 Dashboard 主區域自動縮減讓出空間（不重疊）。
- 面板頂部有收合按鈕，可隨時收回去。

#### REQ-2：面板寬度可拖拉調整

- 對話面板左邊緣可拖拉，讓使用者自行調整面板寬度。
- 設定最小寬度（350px）和最大寬度（550px），避免拉太小看不見或太大擠掉 Dashboard。
- 拖拉時 Dashboard 區域同步調整。

---

### 頂部狀態列

#### REQ-3：系統狀態 Banner

- 在對話面板 header 下方，顯示一行系統當前狀態摘要，例如：
  > 🔴 A 級應變中 | 光復南路封閉 | ETE 90 min
- 狀態資訊由後端經 WebSocket 推播更新（不需要前端自己算）。
- 用色彩區分等級：A 級紅色、B 級橘色、正常綠色（[2026-07-28更正] 顏色對齊 `02-data-contract.md` §8「A 級紅、B 級橘、正常青綠」；原寫黃色會跟 F4 路網圖「次路線黃色虛線」的顏色語意衝突）。
- 常駐顯示，不自動消失。

---

### 訊息呈現

#### REQ-4：雙層訊息結構（氣泡 + 卡片）

- AI 回覆的呈現順序：
  1. **對話氣泡**：一句自然語言摘要（快速看結論）
  2. **Decision Card**：結構化卡片展開完整細節（觸發條款、動作、路網、ETE）
- Decision Card 預設**展開**。
- 使用者的訊息用單純的氣泡即可（靠右、藍色底）。

#### REQ-5：Decision Card 內容元件

Decision Card 應包含以下可辨識的 UI 元件（根據 W1 回傳的結構化 JSON 渲染）：

| 元件 | 說明 |
|------|------|
| **SOP Badge** | 彩色標籤，顯示觸發的 SOP 條款編號與標題（例如「SOP §3 捷運分流」） |
| **判定依據區** | 列出門檻 vs 數據的比較 |
| **預期動作列表** | 編號列出 SOP 規定的處置步驟 |
| **Route Tag** | 路線標籤：封閉路段（紅底刪除線）、主疏散（藍底）、次疏散（灰底） |
| **ETE Badge** | 凸顯預計恢復時間的獨立徽章 |
| **Explain 按鈕** | 點擊展開/收合 AI 的推理過程（模組4 解釋鏈） |

#### REQ-6：延伸問題按鈕

- 每次 AI 回覆下方顯示 2~3 個延伸問題，做成**可點擊的 pill 按鈕**。
- 點擊後自動填入輸入框並送出（等同使用者手打該問題）。
- 延伸問題的內容來自 W1 回傳的 `suggested_questions[]`。

---

### 互動體驗

#### REQ-7：Loading 狀態（步驟進度條）

- AI 處理中時，在訊息區顯示 loading 指示器，包含：
  - 跳動的三個點動畫
  - 「正在推理中...」文字
  - **步驟進度列表**，依序顯示各步驟狀態：
    - ✓ 已完成（綠色）
    - ⏳ 進行中（藍色，可加動畫）
    - ○ 待處理（灰色）
  - 範例步驟：「解析問題意圖 → 檢索 SOP 條款 → 呼叫決策模組 → 計算 ETE」
- 步驟進度由後端透過 WebSocket 逐步推送更新。

#### REQ-8：輸入鎖定

- 當 AI 正在處理回覆時，輸入框鎖定（disabled），送出按鈕變灰。
- AI 回覆完成後自動解鎖。
- 避免使用者連續送出造成錯亂。

#### REQ-9：清除對話按鈕

- 位置：chat header 右上角，用小圖示（例如垃圾桶或重新整理圖示）。
- 點擊後彈出確認提示：「確定清除所有對話？」
- 確認後：清空畫面所有訊息、發送清除請求到後端（讓 W2 也清空 session）。

#### REQ-10：自動捲動

- 新訊息出現時，訊息區自動捲動到最下方。
- 如果使用者正在往上捲動看歷史，不強制捲下來（避免打斷閱讀）。

---

### 快捷問題（初始狀態）

#### REQ-11：預設快捷問題

- 對話剛開啟（尚無訊息）時，在輸入框上方顯示 4~5 個預設快捷問題按鈕，例如：
  - 「目前系統是什麼應變等級？」
  - 「替代路線還有容量嗎？」
  - 「ETE 預計多久恢復？」
  - 「散場機制啟動了嗎？」
  - 「如果 BL17 人數增到 40000？」
- 點擊效果同延伸問題（自動送出）。
- 使用者送出第一則訊息後，預設快捷問題消失，改由 AI 回覆的延伸問題取代。

---

### 視覺風格

#### REQ-12：色調與風格

- 對話面板採**淺色乾淨風**（白底為主），與左側深色 Dashboard 形成對比。
- 使用者氣泡：主題藍色底 + 白字。
- AI 氣泡：淺灰底 + 深色字。
- Decision Card：白底 + 陰影 + 深色 header。
- SOP Badge：依重要性用不同顏色（紅/黃/藍/綠）。
- 整體使用圓角（12px）、陰影（subtle），營造現代感。

#### REQ-13：字體與可讀性

- 主要字體：系統字體堆疊（含 Noto Sans TC 支援中文）。
- 對話氣泡字體大小：14~15px，行高 1.6。
- Decision Card 內容字體：13px。
- Badge / Tag 字體：11~12px。
- 確保在投影機/大螢幕 Demo 時文字清晰可讀。

## 三、資料來源（F6 從哪裡拿資料）

| 資料 | 來源 | 方式 |
|------|------|------|
| AI 回覆（結構化 JSON + 自然語言） | W1 → API | WebSocket 推播 |
| Loading 步驟進度 | 後端處理流程 | WebSocket 逐步推播 |
| 系統狀態 Banner | 後端 P5 級別判定 | WebSocket 推播 |
| 延伸問題 | W1 回傳的 `suggested_questions[]` | 包含在 AI 回覆的 JSON 裡 |
| 預設快捷問題 | 前端寫死（hardcoded） | 無 |

---

## 四、不屬於 F6 的事（明確排除）

- ❌ 判斷使用者意圖（那是 W1 的工作）
- ❌ 記憶對話歷史（那是 W2 的工作，前端不存 session）
- ❌ 呼叫 K3 或 A2（那是 W1 的工作）
- ❌ 計算 SOP 門檻或 ETE（那是後端的工作）
- ❌ 決定 Dashboard 其他區域的顯示（那是 F1~F5、F7 的工作）

---

## 五、成功標準

1. 評審點開對話面板 → 看到快捷問題 → 點一個 → 自動送出 → 顯示 loading 步驟 → 收到完整 Decision Card 回覆。整個流程不需要手打字。
2. Decision Card 中的 SOP Badge、ETE Badge、Route Tag 清晰可辨，投影到大螢幕仍能一眼看懂。
3. 連續問 3 題（利用延伸問題按鈕），對話流暢不卡頓。
4. 收合/展開/拖拉寬度都能正常運作，不影響左側 Dashboard。
5. 點「清除對話」後重新開始，快捷問題重新出現。

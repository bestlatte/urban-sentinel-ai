## 2. 缺口清單（優先度排序，尚未跟隊友確認）

### #1 F7「AI推理過程」敘述文字尚未實作
`decision_trace.py::generate_report_explanation` 目前故意拋 `RuntimeError`，程式碼註解寫「Phase 7完成後接入Bedrock LLM，目前尚未實作」。`orchestrator.py:662-665`有catch住做降級。

F7實際顯示的是**結構化資料**（觸發SOP條款標籤、路線飽和度/容量數字），不是LLM生成的推理敘述文字。簡報用詞「清楚展示AI推理過程」跟目前呈現形式有落差——demo時若評審問「LLM怎麼解釋這個判斷」，需要準備好說法（例如：F7走的是「決策依據透明化」而非LLM敘事，理由是LLM不得竄改事實只能轉述）。

### #2 「一鍵發布」按鈕沒找到
簡報第6、7頁都提到多語簡訊要能「一鍵發布至各通報通路」，`frontend/index.html`、`frontend/js/app.js`搜尋不到對應的發布/publish UI元件，也沒有複製到剪貼簿之類的替代機制。

需要跟隊友確認：是否真的沒做，還是走的是別的關鍵字/機制。

### #3 資料檔名與簡報敘述不一致（2組待確認，1組已釐清）
- `city_traffic_flow.csv`（簡報）vs 實際`data/city_traffic_flow.json`

參考road_network案例的經驗，這2組很可能也只是命名差異、內容沒問題，但尚未逐欄位核對，demo前建議跑一次跟road_network同樣的schema比對。

## 3. 模組間衝突檢查

實際檢查`branch4`程式碼（非只看`INDEX.md`宣稱內容）進行交叉驗證：

### 3.1 確認無衝突的部分

- **`ModuleGateway`跨模組存取層**：`orchestrator.py`／`whatif_engine.py`／`agent/tools.py`全部經過`GATEWAY.xxx()`存取，沒有繞過去直接`from src.rules import ...`——`INDEX.md`宣稱的修正確實落地。
- **`ReasonCode`九值列舉**：`models.py`定義9值（`CLOSED`/`CAPACITY_INSUFFICIENT`/`NOT_IN_ALTERNATIVES`/`NOT_DIRECTLY_INTERSECTING`/`DOWNSTREAM_ONLY`/`FLOW_DIRECTION_MISMATCH`/`SATURATED`/`UNKNOWN_SEGMENT`/`MISSING_TRAFFIC_SNAPSHOT`），`routing.py`實際產出值是其子集，無衝突。
- **SOP-6多語觸發邏輯**：`rules.py`判定（`roaming >= 0.30`）跟`reporting.py`的`multilingual`旗標消費邏輯一致，沒有兩套標準各說各話。

### 3.2 發現的問題

**a. 前端有兩個WS事件監聽是死接線**
`frontend/js/ws.js`有處理`chat.input_lock.v1`、`chat.system_status.v1`的邏輯，但搜遍`orchestrator.py`/`agent/*.py`/`main.py`/`ws_manager.py`，後端從未實際broadcast這兩個事件。不影響系統運作（前端只是永遠收不到觸發），但代表F6對話面板一部分設計功能（輸入鎖定提示/系統狀態提示）沒有真的接通。尚未跟使用者討論是否要處理。

**b. API端點數量遠超steering規範（使用者已表示暫不處理，僅留紀錄）**
`.kiro/steering/00-tech-stack.md` §4明文「API 表面（固定，不得擴充）」，只允許：
```
GET  /api/dashboard
POST /api/incidents/evaluate
POST /api/what-if
GET  /api/health
WS   /ws
```
但實際`main.py`有14個REST端點，多出`/api/simulation`系列（`start`/`play`/`pause`/`reset`/`stop`/`seek`共6個，模擬器時間軸播放用）、`/api/incidents`、`/api/reset`、`/api/incidents/generate`。

> **狀態：使用者已明確表示這點「先不考慮」**，不列入待辦，此處僅作紀錄避免之後重複分析同一件事。
